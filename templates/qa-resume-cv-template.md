## How this example was tailored

| Public-profile fact | Resume decision | Why |
|---|---|---|
| 12 overlapping roles | State **6+ actual calendar years** | Accurate and defensible |
| Many ventures | Compress into one proof section | Keeps the QA application focused |
| Multiple simultaneous jobs | Preserve dates; explain overlap when asked | Never hide or double-count experience |
| Large skill inventory | Group by QA outcome and target JD | ATS-readable; avoids a tool wall |
| Platform-scale numbers | Attribute them to the platform/project | Avoids claiming company-wide metrics as personal output |
| Strong public GitHub | Select 4–5 relevant repos | Evidence beats an exhaustive list |

## Bullet builder

Use this formula for every experience bullet:

```text
[Strong action verb] + [what you owned] + [how/tool] + [scope] + [result]
```

Example:

```text
Built a Playwright + TypeScript regression suite for 5 commerce portals,
cutting release validation from 2 days to 30 minutes in CI.
```

## Final checklist

- [ ] Target title matches the vacancy.
- [ ] Junior/Mid resume is one page; Senior/SDET is no more than two.
- [ ] Every listed tool is defensible in an interview.
- [ ] Top third contains the strongest evidence and matching keywords.
- [ ] Experience bullets describe outcomes—not job descriptions.
- [ ] GitHub projects have README, setup steps, CI and reports/screenshots.
- [ ] Dates, tense, punctuation and capitalization are consistent.
- [ ] PDF text can be selected and copied; links are clickable.
- [ ] Filename is professional: `First_Last_QA_Resume.pdf`.
- [ ] A peer can identify your top achievement in 20 seconds.
